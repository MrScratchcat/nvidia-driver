Quick install

One command on Ubuntu 22.04+ / Debian 12+ / any Ubuntu‑derived distro:

curl -fsSL https://mrscratchcat.github.io/nvidia-driver/install.sh | sudo bash

The script installs kernel headers + DKMS, registers the signing key, pins the lwl repo above any other nvidia source, installs nvidia-driver-595, builds the DKMS module against your running kernel, unbinds nouveau, and loads the new modules. To pick a different package up‑front:

curl -fsSL https://mrscratchcat.github.io/nvidia-driver/install.sh \
  | sudo DRIVER_PKG=nvidia-driver-595-open bash

Manual install

If you prefer to wire up apt by hand:

sudo apt install -y "linux-headers-$(uname -r)" dkms build-essential
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://mrscratchcat.github.io/nvidia-driver/keys/nvidia-driver.gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/nvidia-driver.gpg

echo "deb [signed-by=/etc/apt/keyrings/nvidia-driver.gpg] \
https://github.com/MrScratchcat/nvidia-driver/releases/download/apt-resolute-v1 ./" \
  | sudo tee /etc/apt/sources.list.d/nvidia-driver.list >/dev/null

sudo apt update
sudo apt install -y nvidia-driver-595
sudo dkms autoinstall -k "$(uname -r)"
sudo modprobe -r nouveau 2>/dev/null || true
sudo modprobe nvidia nvidia-drm nvidia-uvm nvidia-modeset
nvidia-smi

Headers are mandatory. nvidia-driver-595 ships as a DKMS module, not a prebuilt kernel module, so linux-headers-$(uname -r) must be installed before the driver. Without them the DKMS post‑install build is skipped silently and nvidia-smi won't find the module.

If you previously trusted an older variant of this repo, the signing key was rotated. Remove the stale key first: sudo rm -f /etc/apt/keyrings/nvidia-driver.gpg /etc/apt/sources.list.d/nvidia-driver.list.

Verify the signature

The repository metadata is signed by the lwl nvidia-driver key. Confirm the fingerprint before trusting it on a new host:

curl -fsSL https://mrscratchcat.github.io/nvidia-driver/keys/nvidia-driver.gpg \
  | gpg --show-keys

The output must show:

pub   rsa4096 2026-05-19 [SCEAR]
      19EA FC08 4457 09DC 0110  D97A FE87 C31F 7473 ACB0
uid                      nvidia-driver repo <info@comexr.com>

To verify the live InRelease against the key:

curl -fsSL https://github.com/MrScratchcat/nvidia-driver/releases/download/apt-resolute-v1/InRelease \
  | gpg --verify

Update the driver

Once the source is registered, updates flow through normal apt:

sudo apt update
sudo apt upgrade nvidia-driver-595

When a new driver version lands here, apt will pick it up automatically on the next apt update.

Remove the repository

sudo apt purge -y 'nvidia-*' 'libnvidia-*' 'xserver-xorg-video-nvidia-*'
sudo rm -f /etc/apt/sources.list.d/nvidia-driver.list
sudo rm -f /etc/apt/keyrings/nvidia-driver.gpg
sudo apt update

Reboot afterwards; the kernel will fall back to the open‑source nouveau driver.

Troubleshooting

NO_PUBKEY or BADSIG after apt update

The signing key was rotated and your installed key is stale. Re‑run the install block at the top of the page — it will overwrite the old key in /etc/apt/keyrings/.

404 Not Found when apt fetches a .deb

Your local Packages cache is older than the published metadata (e.g. after a rebrand). Force a refresh:

sudo rm -rf /var/lib/apt/lists/*
sudo apt update

nvidia-smi reports "no devices" right after install

The DKMS module either didn't build (missing headers) or built but never loaded (nouveau still bound, no reboot). Check the build state:

dkms status nvidia
lsmod | grep nvidia

If dkms status shows nothing, install headers and rebuild:

sudo apt install -y "linux-headers-$(uname -r)" dkms build-essential
sudo dpkg-reconfigure nvidia-dkms-595
sudo dkms autoinstall -k "$(uname -r)"

If dkms status shows installed but lsmod | grep nvidia is empty, unbind nouveau and load the modules:

sudo modprobe -r nouveau
sudo modprobe nvidia nvidia-drm nvidia-uvm nvidia-modeset
nvidia-smi

A reboot is the cleanest fix when in doubt — install.sh handles this automatically.

Secure Boot is rejecting the kernel module

Make sure secure boot is either disabled or the DKMS module is signed with an enrolled MOK. Ubuntu's mokutil walks through this — see UEFI SecureBoot & DKMS.
